## 本次落地

- Android TV **0.14.0-local / 14**、iOS **1.1.3 / 5**：片库及媒体分段的 GET 请求最多发送 3 次，失败后分别等待 300、900 毫秒。每次从相同 URL 与 Range 重新读取，只有完整响应才返回给解密和播放层。
- HTTP 408、500、502、503、504 和可恢复的传输中断进入有限重试。保留连接池、清晰度、签名与分段校验；Android 的截断响应只重新读取失败分段，不重复交付已读字节。
- POST 不在请求层重放。除 408 外的 HTTP 4xx、明确证书拒绝、无效媒体范围、超大响应等不会被当作临时故障循环重试。存在 `Retry-After` 时交回现有错误处理，不进入本次请求级短退避。
- 页面取消或任务取消会阻止后续请求；Android 退避期间每 50 毫秒检查导航取消，视频流仍登记并取消每次实际调用。最终错误继续沿用现有重试入口，静默连播与滑动切集不增加弹窗。
- iOS 模拟器回归发现控制栏显示时下滑可能中断：拖动一开始移除控制栏，会丢失承接手势的视图。现改为拖动时保持视图、仅置透明，并暂停自动隐藏计时；退出前台时清理拖动状态。回归覆盖控制栏可见时下滑和后台返回后的暂停状态。
