## 源码分析与取舍

仓库同时保留 React Native 客户端/Node 服务和 kotlin-tv 原生工程。此次继续使用 Kotlin 原生 View、OkHttp、Media3，单 APK 直接联网，无需给电视部署 Node 服务。复用已有收藏、续播、缓存、请求取消和播放器资源释放逻辑，不引入界面框架或运行时依赖。

原搜索只读取部分 video_data 内容，分组和超过首屏上限的条目会遗漏，跨页也缺少统一去重。本次逐条读取 video_data 数组与 lynx 分组，以剧集 ID 去重；界面每页 24 条，未显示的结果留到后续页面，不按首屏数量截断。排序顺序为完整剧名、前缀、包含和题材/简介；已经显示的页冻结，返回和翻页不会重新移动焦点。

原取址在本机四个样本均返回 110001，尚未进入视频解码。用户指定 jackotom/hongguo-drama 后，对其红果适配器实测成功，并移植临时访客标识、会话 nonce/启动时间与签名一致性；只接受返回的所选分集。算法同源于 drpys，保留已验证的 hash branch 0。详细 GPL 来源见 NOTICE.md。

## 本次界面与内容

- 用户确认 A「客厅片库」：深灰背景、珊瑚色、完整真实海报、焦点描边与底色。首页大屏七列，窄屏/大字号六列；搜索六列。
- 首页读取前三页；本轮漫剧 60 部、短剧 72 部。按真实题材生成五至六个在线分区，保留接着看、收藏有更新与稍后看。缓存保留三页元信息，后续浏览从正确来源页继续。
- 搜索保留电视输入、手机输入、历史、类型选择和分页；上游无响应时显示检索进度，失败可重试，已完成的片库页无需重读。
- 详情使用真实封面、集数、简介及分组选集，保留原有远距离阅读与安全边距。
- 不可播放时显示片源错误和恢复入口，110001 不盲目自动重试；已知不兼容的视频编码继续过滤。

## 搜索覆盖边界

本轮 App 搜索仍为 HTTP 200、空响应，备用来源是官网公开片库。漫剧与短剧分别完整遍历官网可用分页，实测各 800 部；“修仙”60 个去重匹配、3 页，“总裁”143 个去重匹配、6 页，均遍历到末页。两个首页完整剧名查询首条准确命中。

这能保证本次公开片库与已返回接口结果不因客户端截断而遗漏，不能证明红果 App 全站片库完整。结果受官网覆盖、更新、网络及上游接口状态影响。首次构建官网索引需要等待；同类型索引在内存缓存十分钟，查询页会话五分钟。到达接口 100 来源页上限时会明确提示，不假装已检索全站。

## 安装与使用

文件 hongguotv-0.10.0-local-android8.apk，包名 com.hongguotv.nativeapp，versionCode 10。安装到 Android 8 或更新的电视/盒子；允许所用安装器安装 APK，打开后直接联网使用。方向键选片，确认看详情或续播；播放时确认暂停/播放、左右快退/快进、下键选集、上键更多，返回先收起控制再退出。

本次是本地测试签名包。若设备已有同包名的正式签名版，系统可能拒绝覆盖安装；先通过原版片单备份保存记录，后续应使用相同正式签名制作升级包，不要直接卸载以免丢失收藏与进度。当前工作没有卸载或修改实体电视，也没有读取发布私钥。旧 React Native 包 com.hongguotv 可与原生版并存。

## 可复现构建

需要 JDK 17、Android SDK 36，解压源码后在仓库根目录运行：

```sh
./kotlin-tv/gradlew -p kotlin-tv :core:test :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug --console=plain
./kotlin-tv/gradlew -p kotlin-tv :core:run --args=--browse
./kotlin-tv/gradlew -p kotlin-tv :core:run --args=--playback
```

APK 在 kotlin-tv/app/build/outputs/apk/debug/app-debug.apk。本轮主机通过本地网络代理访问依赖与上游接口；电视模拟器独立运行，实际电视网络与硬件解码仍需现场验证。联网 Probe 依赖当时来源状态，离线测试不会保证未来接口可用。

源码 ZIP 包含当前所有修改、新增源码和测试、Gradle 包装器及 GPL 声明；排除本机 SDK 路径、缓存、依赖、签名材料与原始网页采集文件。项目整体许可证与原生派生许可证沿用原仓库，详见 LICENSE 与 kotlin-tv/LICENSE。
